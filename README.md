## 2.5.5 读取与邮件性能优化

Lark各表字段与记录读取重叠执行，同一个LarkStore最多3个GET在途；分页、关联校验与版本计算保持。只读页面请求可合并正在进行的整库/工作流读取，不缓存已完成结果；本地写入前后都会使合并读取失效，保存、预览与审核仍使用独立的新读取及版本冲突检查。

未开启或尚未到期的自动催促仅读工作流配置，不扫描五张业务表、不进入写入队列。到期后在写入锁内重新确认设置，再核对待办、间隔与发送状态。审核列表GET不再排在长时间邮件写入后；工作流列表复用已有行计算邮箱状态，避免再读一遍工作流。已确认邮件发送与投递查询不再扫描业务表；同一封邮件的草稿和发送共用一次新读取的授权，后续邮件仍重新核对授权。页面启动的连接状态与业务数据请求并行。

模拟测试：3个同时整库读取由33个数据接口请求合并为11个，GET峰值3；不代表真实页面固定提速3倍。通过performance、Lark分页/版本冲突/批量恢复、lifecycle、invites、autofill、submission、Render启动和登录检查。未操作生产Lark数据或发信。单次整库读取仍读取全部业务表以保持完整版本校验；Render免费实例休眠及真实网络/Lark延迟仍需部署后观察。手动部署后build为2.5.5。

## 2.6.6 Lark 浏览与保存优化

## 2.6.7 添加达人及启动读取优化
