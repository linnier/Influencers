# 2.6.5 合作邮件标准模板与项目要求

部署：Render → itea-creator-manager → Manual Deploy → Deploy latest commit，Live后刷新网站，build应为2.6.5。代码上传不代表已部署。本次未向真实达人发信，也未改写已有邀约、通知、项目或报名记录。

## 填写和预览

项目 → 邀约与报名 → 通知设置，新增中文/英文拍摄与发布要求、中文/英文优惠券使用说明，各项最多2000字。可以填写产品/门店、形式数量、必拍画面、文案重点、标签、初稿审核和发布/回填时间。中英文须成对填写或同时留空，不自动翻译。留空时邮件使用请回复确认要求、查看券面规则的双语提示，不编造具体门店/有效期。

“预览四类邮件”使用当前尚未保存的输入与明确标注的虚构达人/账号/链接，仅展示，不创建邀约或发信。保存全部设置后，新邀约、确认合作、登记发券和催促使用本项目要求。已有自定义模板保留；可点击“使用已确认的标准模板”填入新文案，项目要求、合作权益、日期及通知开关保持，预览后保存。已知的旧内置文案仅读取时升级为标准内容，不自动写业务记录。旧客户端保存设置时不会清空新要求字段。

## 四类邮件

邀约、合作确认、发券确认、催促均使用已确认中英双语文案，统一落款：

Best regards,
itea Branding Team
collab@itea.sg

合作金额及优惠券合称合作权益，只显示实际提供的非零部分；未知权益标明待确认，不自动换汇。四类模板集中管理，页面与后端共用占位符规则，兼容原合作金额、券数量、截止日期等变量及初稿中的要求变量别名。

合作确认列明实际确认的平台账号。发券通知再次列明：项目、领券账号、本次/累计/约定券数、发券日期、已确认合作权益、发布平台和对应账号/主页、发布截止、拍摄发布要求、优惠券使用说明、专属回填入口，并明确本信不确认合作费用支付。账号清单只从本项目已确认且有效的合作取数，排除未确认、取消及其他项目账号。催促分中英文列出实际待补事项，保持原冷却期、审核中暂停及确认发送逻辑。

## 保存和发送边界

新文案只用于之后创建的邮件。已生成的邀约/通知正文为历史快照，不自动替换或重发；已有确认、发券、批量发送/取消、共享邮箱授权、权限、签名链接及重试保护保持。登记人工发券仍不接入券系统。自动邮件继续遵循原项目通知开关；模板预览不会触发邮件。

通过check、新增mail-template测试、生命周期/本地HTTP与JSDOM设置预览、邀约/共享邮箱/批量发送取消、权限脱敏、Render启动、原状态和性能检查。覆盖金额/券数合并与零金额省略、精确落款、四类实际渲染、项目字段保存/中英成对/长度校验、旧默认升级/自定义保留/旧客户端兼容、确认账号范围排除、全部占位符替换、历史快照保持、预览及重复发券不额外发送。新模块静态资源已加入网站资产白名单。未验证生产Lark保存及真实浏览器视觉布局。
