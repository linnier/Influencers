# itea 性能优化与部署

2.6.34 减少邮件和表单的重复查询，并为静态页面及脚本增加 gzip 压缩。

## 已包含的代码优化

- 入库表单及账号验证按工作流 ID 读取记录，避免为一个表单或一个账号下载整张工作流表。
- 发送邀约时复用本次写入锁内已读取的授权记录；下一次操作仍读取当前状态。
- 已知工作流记录在提交报名及准备邀约时直接复用，减少整表重复查询。
- 审核列表浏览复用现有短期业务数据缓存；提交及权限核对保持实时读取。
- 静态 HTML 和 JavaScript 在进程启动时预先压缩；浏览器支持 gzip 时发送压缩版本。不压缩个人资料 API，也不放宽页面权限。

本地测试样本中，静态资源传输体积从 1,103,861 字节降至 384,792 字节，减少约 65.1%。这是传输体积变化，不代表线上操作速度提升同样比例。5,002 条工作流记录的模拟测试中，入库表单 GET 仅返回匹配的一条记录。

## Render 中需要检查的设置

仓库 `render.yaml` 配置为新加坡区域的免费实例；实际服务可能已在后台调整，以后台为准。

1. 在 Render 打开 `itea-creator-manager`，手动部署最新 GitHub 提交。
2. 如果仍使用免费实例且希望避免休眠后的唤醒等待，可在实例规格中选择常驻运行的付费方案。价格以 Render 后台显示为准。
3. 等部署状态为 Live 后刷新网站。首页正常打开后，再核对邮件预览、报名表和审核列表。

本次代码提交不修改实例规格，不触发付费升级，也不自动部署。

Lark 邮件和多维表格仍由外部接口处理，实际耗时及发送限额由 Lark 决定。代码优化减少重复工作，常驻实例改善休眠后的首次访问；两者处理的等待环节不同。
