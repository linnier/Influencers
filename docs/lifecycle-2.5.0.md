# 2.5.0 上线说明

本版落实已确认的交互预览，业务数据继续存放于原Lark Base。不会在部署时自动邀请达人、发送历史合作通知、发券或修改现有达人与Post。自动催促默认关闭。

## 部署

Render → itea-creator-manager → Manual Deploy → Deploy latest commit。保持现有环境变量、共享邮箱授权、邮件权限和回调地址；无需重新创建Base。等待Live后登录，访问 `/api/connection`，build应为 `2.5.0`。本仓库关闭自动部署，上传GitHub与正式站上线是两个步骤。

## 达人入库

主导航“达人入库”包含“达人手动入库”和“达人申请入库”。原有手动表单与Excel批量新增保留。申请入库内设置表单标题、说明和是否开放，点击生成后提供完整公开链接及复制按钮。公开表单不显示内部名单。

达人填itea领券账号、邮箱、联系方式、地区以及各平台完整主页和粉丝量。itea账号、主页所对应的平台账号用于匹配；不单凭邮箱合并达人。每条申请先审核，旧字段默认保留、空值默认补充，粉丝量分平台审核，留空不清空旧值，真实零保留。冲突不能自动绑定。新达人需由审核人填写负责人；Lark成员字段须使用已配置映射的负责人。通过后保留审计记录，旧达人原合作关系不变。退回后可联系达人通过同一公开表单重新提交正确资料。

## 合作通知与回填

项目“邀约与报名”增加“通知设置”“邮件通知”“Post回填审核”。通知设置统一保存本项目邀约默认金额、券数、报名截止、标题及模板；筛选邀约时可调整本次内容。合作确认与发券通知默认开启，但只由新发生的业务动作触发；批量确认时逐人处理。

确认合作后生成达人专属私密回填链接，邮件包含约定金额、券数及发布截止。人工发券仍在外部券系统完成，网站只登记实际结果并发送通知；相同登记批次不会重复记券。专属入口展示本人的当前项目、回填记录和退回原因。也可在回填审核页手动获取某位已合作达人的链接。

回填先待审核，通过后创建或更新同一篇正式Post；已有价格、投流费和券数保留，达人不能修改这些字段。互动明细按点赞、收藏、分享、评论汇总。提交暂不替换正式Post；可退回补数据。

邮件通过已授权的 collab@itea.sg HTTPS Mail API发送，接入方式沿用2.4.18。发送失败不撤销业务结果；可核对收件邮箱后只重试通知。发送中、结果未知、已提交邮箱的邮件不能再次发送，需在Lark邮箱或投递查询中核查。

## 催促

未回填、待补数据、退回补充可批量催促，先预览每封双语邮件，发送时再次核对未完成事项。待审核内容暂停催促。默认间隔72小时，自动催促默认关闭；启用后默认截止次日起开始，最多自动3次，可调整。达到上限后由团队人工跟进。

服务器每分钟检查启用的规则；Render Free休眠时无法保证准时，恢复运行后继续检查。可点击“按已保存规则检查到期催促”。已有未知或失败通知阻止重复催促，需先核查或重试原通知。私密回填链接持有者可提交该达人的本项目内容，须仅发给本人。

## 验证

`npm run check`、`npm run test:lifecycle`、`npm run test:invites`、`npm run test:lark`、`npm run test:render`、`npm run test:login`、`npm run test:creator`。通知接口测试使用模拟邮箱，不发送真实邮件；本地SQLite联动测试验证实际表单生成、提交、审核及达人库人数更新。真实Lark和邮箱结果需部署后核对。

上线后先核对项目人数、平台账号与历史Post；生成入库表单但可先暂停接收。以测试达人试填一条、审核后核对邮箱和平台粉丝量，再安排真实邮件。


## 2.5.1 表单响应修补

部署最新版后，build应为2.5.1。后台生成表单不再读取整库资料，保存后直接返回链接；按钮立即显示正在保存，慢响应和失败均可见。公开入库表单仅读取配置，GET不等待业务写入锁；读取超时可重新读取，提交不盲目重试。原有表单链接、邮箱授权与申请记录保留。检查新增真实按钮点击及公开表单前端载入、整库读取失败时独立生成表单、写入队列被占用时公开配置读取仍可完成。

## 2.5.2 审核结果展示

将入库申请处理结果的原始JSON替换为中文状态、处理说明、审核时间（GMT+8）、字段与平台账号粉丝量前后对比；现有审核快照直接可用。仅前端展示调整，不改业务数据。验证新达人通过后查看结果、旧达人差异、空粉丝量与真实0、HTML转义、旧记录缺少快照。整体UI与资料自动填写仍仅供预览。

## 2.5.3 上线内容与检查

正式UI接入品牌绿与标准/紧凑密度，保留原手动表单、Excel批量入库及业务逻辑；密度只保存在当前浏览器。

旧达人自动填写位于现有公开入库申请表。填写itea账号和原登记邮箱，点击获取验证码，从collab@itea.sg发送；邮箱验证码验证后，仅带出本人白名单资料及平台信息，不包含负责人、备注、项目或内部ID。资料变更后提交仍待审核。无旧邮箱时可手动提交，由团队核对；库内重复itea账号不开放自动填写。

验证码随机生成，仅保存于服务内存中的HMAC摘要，10分钟有效、最多5次错误尝试、成功后销毁；重启失效。每个账号和邮箱每15分钟最多3次请求且间隔至少60秒，全站每小时最多100次。不确定是否发出邮件时不自动重发，也不开放读取。未匹配请求使用相同的通用响应。验证码不写入Base，不增加长期数据表。

运行npm run check、test:autofill、test:lifecycle、test:invites、test:render、test:login均通过。验证码发信测试使用mock，无生产发信或Lark写入。实际邮箱投递与浏览器布局需部署后核对。

部署：Render的itea-creator-manager服务点击Manual Deploy → Deploy latest commit，成功后刷新；查看/api/connection的build为2.5.3。原公开链接继续有效，原有资料和授权保留。未改变未来自动部署设置。

## 2.5.4 申请提交保护

公开表单提前校验个人主页与粉丝量，不自动解析分享短链。申请POST没有盲目重试；显示提交中并防止双击，网络中断后不推断是否保存，恢复按钮、保留字段并提供复制备份。草稿仅存于当前浏览器标签页sessionStorage，最多24小时，刷新恢复时不恢复勾选确认，成功提交后删除；不缓存验证码。跨浏览器或不同手机不会自动同步草稿。

验证npm run test:submission、test:autofill、test:lifecycle与test:render通过。真机连接失败尚未复现；此版本是输入校验、错误反馈及数据保留修补，不是已证实的网络连通修复。
