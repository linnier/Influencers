# 2.6.4 批量取消待发送邀约

部署：Render → itea-creator-manager → Manual Deploy → Deploy latest commit，显示Live后刷新网站，build为2.6.4。本次仅上传代码，没有取消任何生产邀约或操作真实邮箱。

## 使用

项目 → 邀约与报名 → 邀约记录，勾选或全选待发送 → 批量取消待发送 → 核对收件人 → 确认取消。成功记录保留并标记“已取消发送”，不再进入批量发送；展示逐条结果及取消/跳过数量。

取消范围仅为网站中尚未发送的邮件。发送中、已提交邮箱、已送达、结果未知或已进入报名流程的记录会跳过，不能撤回Lark已接受的邮件，也不删除Lark草稿。原报名链接、报名和合作保留。此版本不提供恢复待发送操作。管理员可操作全部项目；负责人仅本项目；查阅账号无修改权限。

## 并发与失败

预览前重新读取状态，确认后逐条调用服务端。取消与发送共用原工作流写锁：若取消先完成，旧页面发送请求也不再发送；若发送已先完成，取消会跳过。每条重新检查当前身份、真实项目归属、确认标记、邮件digest、最新状态、发送记录及报名记录，防止伪造project字段越权。记录取消时间与操作人，重复取消为幂等操作。

遇网络或保存失败停止后续操作，重新读取状态并提示核查，不自动重试不确定写入。列表与服务器校验都排除已提交/发送中/结果未知。取消结果窗口显示实际取消及状态变化跳过明细。

## 验证

通过语法、工作流及共享邮箱模拟、真实本地HTTP角色/归属权限、JSDOM批量确认取消、Render启动和performance检查。覆盖确认/digest校验、记录保留/重复无副作用、旧发送请求不发信、发送/未知/报名状态跳过；在预览后改变记录状态，确认只有待发送被取消并显示明细。取消测试无邮件及草稿调用，原批量发送中断和恢复测试仍通过。未执行生产取消、生产邮件撤回或实际浏览器视觉检查。
