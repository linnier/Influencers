# Post 发布日期筛选与首次载入（2.6.39）

总览、Post 数据和项目总览增加开始、结束日期，以及本月、上月、清除日期按钮。默认不限日期，清除只移除日期条件，保留平台、项目、负责人和搜索。首尾均包含；可只填写一端。无发布日期或无效日期的内容在启用日期时排除，不单列未知日期记录或数量。快捷月份基于新加坡日期，支持跨年与闰月。查询纯前端处理，不修改原始数据，不发邮件。

筛选按合作确认日期影响合作人数，并按发布日期影响已发布 Post 数量、内容累计指标、对应 Post 明细及其已记录费用；投流费用卡片仍可按原项目与币种下钻，并保留日期范围和其他筛选。分页在日期条件变化时重置。报名人数、跟进和完整项目预算保留原范围。达人库、合作执行、报名和发券操作不按 Post 发布日期删减；相关页面隐藏日期控件。

展示的是选中内容的已记录累计表现，不能由此计算某期间新增曝光或阅读。

日期模式下费用包括选中 Post 的合作费用、投流费用和已记录券费；人工发券台账、历史合作券费及按人分摊的券包费用没有 Post 日期归属，本次不计入。分摊达人不改用券数估算，防止重复或改变记账规则。保留完整项目预算，隐藏不具可比性的预算余额。清除日期恢复原有完整统计。不新增“总费用（含券）”项目列。

## 首次载入

首次读取前立即渲染加载状态。主数据与连接元信息并行请求、独立处理，主数据返回即可渲染，不等待连接元信息。连接信息失败或格式错误不再阻止显示数据。主数据响应及 JSON 读取最多等待 45 秒，连接元信息最多等待 10 秒；超时后显示失败提示，可手动刷新。相同页面内并发刷新共用一个读取任务。超时请求的迟到响应不更新页面；没有自动重试保存或邮件操作。8 秒未返回时提示仍在读取，不将尚未读取的数据显示成 0。

真正的 Lark/网络等待仍可能存在；此修复不承诺无网络等待，也不使用浏览器持久缓存存储联系人资料。

## 验证

- `npm run test:date-filter`：带 /creators 路径的真实本地 HTTP + JSDOM；边界、单边、无日期、非法范围、月份快捷、组合筛选、投流下钻、项目总览、查阅权限、费用范围、无数据写入。
- `npm run test:startup`：延迟/损坏连接元信息、主数据延迟/失败/超时、无需点击自动显示、刷新去重、超时后的迟到响应不覆盖新结果。

## 合作人数日期口径修正（2.6.39）

日期范围同时应用于总览合作达人数和项目执行进度中的合作人数，按实际合作确认日期筛选并按达人去重；日期未知的历史导入合作不计入期间人数，不单列未知人数或未知内容日期计数。清除日期恢复完整历史统计。合作逻辑、历史标记和原始数据不改变，不用 Post 发布日期或跟进日期推测合作日期。

Post仍按发布日期筛选：历史合作达人在所选期间发布的内容仍可计入Post指标，不能用合作日期排除这些内容。报名待合作、跟进与完整预算保持原口径。项目执行进度的约定数保留全周期，并明确标注。

## 页面范围修正（2.6.40）

项目列表、合作执行、报名、邀约和发券页面隐藏且停用公共日期条件。仅近期项目总览、独立Post数据、项目内Post数据和项目总览使用日期条件；切回这些页面保留之前所选日期。项目列表发布数在隐藏条件时使用完整统计。
