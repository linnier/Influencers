# 项目成果报告（2.6.43）

入口：项目管理 → 进入项目 → 项目总览 → 下载项目报告。报告在新标签页打开，沿用当前项目、平台、负责人、搜索与日期条件。仅管理员和原本具备导出权限的负责人可用；共享查阅账号的按钮禁用，报告页面与读取API均由服务器拒绝。

## 输出与交互

- 17项可选KPI：合作达人、已发布Post数量、实际券数、阅读、互动、CPV、CPE、互动率、每千Views成本、CPM、自定义阅读口径CPC、曝光，以及预算、合作费、投流费、券包费、已记录费用合计。
- 默认不选费用。按实际显示的章节连续编号，隐藏费用不会跳号。
- 采用经确认的紧凑版式；PDF仅展示阅读量前五的内容榜单，不放完整Post明细、下一步资料或独立计算说明章节。阅读未知的内容不参与排序，真实0保留；同一达人多个Post可以分别上榜。
- 可生成标准、简洁或数据复盘的一段话文案，仅读取所选且可用的指标。自动文案随选择更新；手工修改的文案保留，可点击生成重新计算。不自动判断表现优劣或声称目标已完成。
- Excel提供项目汇总、费用明细、达人明细、Post明细、统计说明，含已选KPI、数据来源和公式。原始明细、实际发券账与金额单独保存。阅读、互动、曝光、合作费/投流费、费用合计和券数使用带缓存值的公式关联明细；券包分摊金额保留为独立已记录值，不能用券数反推。
- PDF使用浏览器打印功能：点“预览 / 保存 PDF”，在打印窗口选择“另存为 PDF”。不依赖服务器安装Chromium或新增付费PDF服务；选项较少时可排一页，内容较多时自动分页。

## 数据口径

Views直接使用总播放／阅读量（含投流），不扣除或重复叠加投流量。互动总数优先使用已填总数，否则按已填细项累计，每篇仅计一次。

按用户选择，报告成本指标使用当前范围内已记录费用（含券）与已知汇总分母计算，不要求每篇Post同时有费用和指标；所以可能与原页面逐Post配对计算的CPM/CPE/CPC不同。缺失不补0；分母为0或全未知则待补。不同币种分别展示成本和比率，不换汇、不相加。比率为阶段性估算，不代表最终完整成本。

合作人数按达人ID去重，日期筛选时按真实确认日期，未知日期的历史导入不算期间人数。Post按发布日期筛选，不因合作确认在别的期间就丢弃本期发布内容。

实际券数沿用已记录Post券数、历史合作券数和人工发券记录，金额分摊不改变券数。费用复用现有FeeOverview汇总，保持券包分摊替代估算、无重复记账等规则。启用发布日期时，未关联Post的人工发券、历史合作券费和分摊费用不计入；项目预算保持完整额度。

## 一致性与权限

API为只读GET `/api/reports/project`。从现有业务/工作流数据生成过滤后的报告模型，不接受客户端上传报告数值，不发送邮件或修改原业务记录。使用软删除后的可见数据和当前有效账号权限。页面传入已显示版本，服务器版本不一致返回409，要求刷新项目资料后再生成；打开报告后的Excel和PDF使用同一个带生成/同步时间的快照。

报告正文仅说明搜索条件已应用，不回显可能包含联系方式的搜索文字。输出不包含档案中的邮箱、联系方式、itea领券账号、内部标签、内部备注、原始导入资料或邮箱授权。所有HTML文字转义，Excel用户文本按字符串输出，只有程序生成的数值公式可以执行。

## 测试

`npm run test:project-report`：模型边界和真实 `/creators` HTTP/JSDOM页面，覆盖未知/0、部分数据、分币种、实际券数与分摊金额、日期及组合筛选、跨账号人数去重、TOP5、无隐私字段、服务端403和409、Excel公式、费用及连续序号、项目按钮和无业务写入。另通过真实本地HTTP+Chromium验证17项选项、Excel下载、PDF排版与手机宽度；数据均为本地合成记录，无真实邮件。

当前线上部署目录和容器名需按服务器现状核对，不应直接套用已经不存在的旧容器/路径。本次发布代码本身不改变线上Nginx配置或部署目录。
