# 2.6.3 双语报名、管理员改名与批量邀约确认

Render → itea-creator-manager → Manual Deploy → Deploy latest commit，Live后刷新网站，build应为2.6.3。本次上传代码，没有操作正式项目名称、发送真实邮件或修改报名记录。

## 达人合作报名中英双语

原专属和公开合作报名链接继续使用。页面标题、合作金额/券数/截止时间、姓名、邮箱、itea领券账号、WhatsApp/微信、地区、备注、平台账号/粉丝数/主页、增删账号、隐私确认、审核说明、加载/提交/已报名/成功/失败提示同时显示中英文。小红书选项显示Xiaohongshu但提交值保持小红书，原接口和字段不变。用户输入的项目名称和备注不自动翻译。服务端详细错误保留原文，并提供英文处理指引。

## 管理员修改项目名称

管理员进入右上角系统管理 → 修改项目名称，选择项目并填写新名称保存。只改变原项目的名称，ID、负责人、合作、Post及原报名链接保持。原已创建邮件的正文和主题保留历史内容，不重发。

后端专用管理接口在写锁内重新检查管理员身份，核对项目仍可见、原名称未变，新名称去空白后为1至100字且不与其他项目重名；写入保留乐观版本检查及管理记录。已有项目名称通过整库保存API修改时，负责人也会被拒绝；负责人仍可修改自己项目的其他授权字段。查阅账号不能操作。系统管理表单自动带出当前名称。

## 批量确认邀约

项目 → 邀约与报名 → 邀约记录，勾选或全选待发送 → 批量预览并确认发送。可清空选择，显示选中数量。预览逐人列出邮箱、平台、合作费、券数和截止，以及每封个性化邮件正文。取消预览不发送。

打开批量预览前先重新读取状态，只保留待发送邀约。用户确认后逐封调用原有带digest确认、权限和幂等保护的发送接口，各封仍独立收件和独立报名链接。已发送、发送中或结果未知不能勾选；失败停止，重新读取状态，提示核查，不自动重试POST。确认中防止重复点击。发送中断后只选择仍待发送的记录，结果未知先在Lark邮箱核实，避免重复发送。
