# 2.6.0 账号权限与回收站

部署后查看 `/api/connection` 的 build 为 2.6.0。先使用现有 team 账号登录，它保留为内置管理员，密码仍由 Render 的 TEAM_PASSWORD 管理。页面右上方出现“系统管理”。若此前team密码曾给同事共用，请在Render的Environment中更换TEAM_PASSWORD并保存部署，仅向管理员提供新密码；普通同事改用新建账号。原team密码持有者仍可作为管理员登录，不能仅靠新建低权限账号限制已有管理员凭据。本次仅上传功能代码，未创建真实账号、交接负责人或删除正式数据。

## 配置账号

在“创建账号”中填写唯一登录名、至少12位初始密码及角色。负责人账号须绑定与现有资料完全一致的负责人名称，可参考下拉提示。负责人名称只能绑定一个启用账号。共用查阅账号选择“共用查阅账号”，不用绑定负责人。管理员也可创建其他管理员账号。

管理员可调整账号角色、重置密码、停用和重新启用账号。原负责人仍有负责资料时，先交接再调整其角色或绑定。重置密码、调整角色、停用账号均使原会话失效；内置team账号不在停用列表中。账号密码只保存带随机盐的scrypt摘要，不在列表或API响应中返回。Lark模式账号保存在现有协作工作流表，避免Render重启丢失。

## 权限范围

- 管理员：管理全部资料、账号、项目负责人、全局达人申请审核和邮箱授权；移入回收站、恢复及查看管理记录。
- 负责人：查看全部项目和资料，只能修改绑定负责人名称下的项目。允许处理本项目邀约、报名、回填和费用等；不能给自己接管其他项目或修改他人项目的Post。共享达人资料只能由其原负责人或管理员修改；全局达人申请入库审核及表单设置由管理员管理。
- 共用查阅账号：查看全部项目、Post、效果、统计及费用；服务器不返回邮箱、联系方式、itea领券账号、备注和原始导入资料等可能包含联系方式的字段。邀约、报名、回填、催促及通知的真实状态仍可查看；邮件正文、可能含联系方式的处理说明、模板及专属填写链接不返回。不能修改、发信、审核、导出或进入系统管理。可见页面的数据仍可被人工阅读或复制，禁止导出指网站不提供导出功能且导出API被拒绝。

角色校验在服务器执行。写入进入队列后重新核对账号状态及项目负责人，防止交接后继续执行排队的旧操作。网站角色不会修改Lark Base本身已有的访问权限。

## 分配和交接负责人

“分配项目负责人”可选择单个项目和有效负责人账号，调整项目及项目内合作的负责人，达人库归属保持。

“负责人批量交接”会调整原负责人全部达人、项目和合作记录（含归档资料），完成后停用原绑定账号。有负责资料的账号停用时也必须指定接任负责人。当前登录账号不能停用自身。管理员操作由操作者账号记入管理记录。

## 删除和恢复

在系统管理选择项目、达人、平台账号、合作记录或Post，点击“预览删除影响”，核对涉及数量，输入名称及删除原因，再移入回收站。删除项目隐藏其合作与Post，不删除达人库；删除达人隐藏其账号、合作与Post。所有原记录保留在Base/SQLite，删除状态存于工作流元数据，不执行永久删除。

回收站支持恢复。恢复父记录不会覆盖子记录独立的删除状态，必要时分别恢复。统计按剩余可见记录计算，合作阶段需人工核对。已删除项目的报名链接停止接收；已删除合作的回填入口停止开放。其他记录的保存会保留隐藏原记录；旧页面若携带已删除记录提交会被拒绝并要求刷新。

## 验证与运行说明

通过语法、真实本地HTTP角色与删除恢复测试、JSDOM管理页面交互，以及原有状态、Lark分页/冲突/批量恢复、性能、报名/回填、共享邮箱、登录、验证码和提交恢复测试。覆盖费用可见、联系方式不返回、禁导出、越权修改拦截、独立管理员、角色变更/密码重置会话失效、项目分配/离职交接、级联软删除/恢复、隐藏数据保存保留和重启连续性。

测试未访问生产Lark或生产邮箱，浏览器视觉布局和实际Lark部署仍需上线核对。后台账号校验及删除可见性需读取工作流元数据；保留2.5.5对在途请求合并、并发读取和闲置催促跳过的优化。Render免费实例休眠仍会影响首次访问。
