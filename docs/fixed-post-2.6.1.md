# 2.6.1 固定字段 Post 导入

在 Render 的 itea-creator-manager 服务选择 Manual Deploy → Deploy latest commit，等待 Live 后刷新网站，/api/connection 的 build 应为 2.6.1。本次仅发布代码，未访问生产 Base 或发送邮件。

## 使用

项目管理 → 批量导入 → 下载 Post 固定模板.xlsx。在 Post导入 工作表第2行开始填写，每行一篇 Post。模板包含20个固定字段及独立填写说明，说明页不参与导入。项目在网站选择；新项目填写名称、默认负责人，已有项目自动带出默认负责人及币种。上传自动预览，核对后点击导入检查通过的记录。

字段：序号、平台、昵称、粉丝数、账号链接、itea账号、联系方式、邮箱、发布日期、发布链接、曝光量、播放量、互动量、点赞、收藏、评论、转发、关注、发券数量、项目负责人。兼容用户原中英双语表头和旧版导入。原多平台工作表及草稿仍可用，草稿与 Lark 字段工具折叠展示。

## 数据规则

- 平台、昵称、完整个人主页及完整发布链接必填，一行一个平台、一篇Post；不解析小红书分享短链接。
- 实际发布日期填写 YYYY-MM-DD 或 Excel 日期，未知留空并在预览核对；9.21-9.27 等日期范围不能作为实际发布日期，不能推断年份。合作确认日期另行填写，原合作日期保留。
- 粉丝数及指标为非负整数，支持 K、万等数值；空白为未知，真实0保留。曝光量、播放量及平台总互动分别保存，明细不与总互动重复累加。错误数值显示工作表和行号。
- 发券数量为本行实际计入的数量，同一合作多篇只在一行填总券数，其余填0；未知留空。券成本沿用每张SGD3。没有合作费列时费用保留为未知；可额外添加合作价格列并指定原币种，不换汇。
- 项目负责人列用于新合作和新达人的归属，空白用默认负责人，不修改已有项目、达人或合作负责人。服务端保持2.6.0权限及回收站校验。
- 新达人保存itea、邮箱及WhatsApp/微信；已有达人邮箱、联系方式与粉丝数保持不变，补充资料仍在达人库审核更新。itea唯一匹配可为旧达人新增平台账号；重复itea、账号归属冲突会阻止导入，昵称或邮箱不能单独合并达人。
- 同项目同账号已有Post跳过，不覆盖指标；属于其他项目或账号时提示冲突。缺必填列、重复列、缺昵称或平台均明确报错，不静默跳过非空行。
- 自动分批保存；预检无写入，遇失败停止并提示核查，不自动重试不确定的写入。部分保存后重新读取、预览会跳过已有内容。

如提示Lark缺字段，由管理员展开“匹配草稿与 Lark 字段工具”准备字段后再预览。准备工具现覆盖缺失的itea、邮箱、联系方式及粉丝数字段。字段准备完成不代表Post已导入。

## 验证

新增 test:fixed-post：模板下载、真实xlsx读写、20列与双语表头、未知/0、错误列/日期/邮箱/数字/链接、归属冲突、既有资料不覆盖、权限和脱敏；本地HTTP/SQLite及JSDOM上传33条跨三平台Post，逐批服务端校验保存与重复跳过。通过 check、bulk、multi、bulk-ui/batch、Lark模拟、access、Render启动、原状态及performance检查。Lark测试补充缺少邮箱/联系方式/粉丝数时幂等准备字段。未验证生产Lark保存和真实浏览器视觉布局。
