# 品牌双语图文邮件（2.6.45）

合作邀请、合作确认、人工发券通知和实际待办催促使用同一品牌版式：原版绿色 itea 字标居中，页眉右侧留空，页脚仅保留团队签名和邮箱。标识来自用户提供的《品牌视觉识别系统》PDF第24页原版矢量内容的等比例透明PNG呈现，不使用生成的Logo。遵循用户最后确认的纯字标方案，不添加页脚组合标志或Slogan。

绿色 `#307044`、深绿 `#183F26`、米白 `#F7F7F2`、金色 `#D3B86C`。标题26px（手机24px），中文正文15px／英文13px，行高1.8，章节间距30px，桌面内边距32px。字号是邮件适配值；字体栈优先MiSans，客户端没有安装时回退到Arial及中英文系统无衬线字体，不假设收件邮箱支持远程字体。

## 模板、变量与中英对照

- 标准模板改为每个字段、段落及模块相邻的中英文对照，不再整封先中文再英文。沿用已有项目、权益、截止日期、账号、券数、待办和报名／专属入口变量，不写死预览中的11月项目、10张券、示例账号或日期。
- 双语项目字段有相同段落结构或相同行数时按对应段／行交错；结构不同则在同一模块内保留完整中英原文，避免丢失、猜译或错误对齐。
- 升级时仅识别旧版原始标准模板并在读取时使用新标准，不覆盖用户自定义文案，不自动保存设置或修改业务记录。自定义文案仍会得到统一品牌外框，但不会擅自翻译或重排任意自定义内容。
- 仅程序认识的标题生成模块。正文一律先转义，不执行用户输入的HTML。只允许http(s)链接，不接受带账号密码的URL；报名／个人入口的按钮使用记录里已生成的专属链接。

## 快照与邮件格式

新邮件记录在原纯文字快照旁保存一个紧凑的 `mailDesign`：版本1、邮件类型、固定按钮链接及可用的券数。收件人、实际券数、回填任务与权益沿用原流程。保存的是文本与排版参数，不保存展开HTML和Logo二进制，以遵守飞书工作流单记录19000字符的现有限制。

`public/mail-design.js` 同时用于服务器与网页，版本1的设计和已保存文字在发送时共同生成HTML，预览使用相同渲染器。未来改版需新增设计版本并继续支持旧版本，不能更改已审批快照的版式参数。旧记录没有 `mailDesign` 时继续按原纯文字发送／查看，不追溯美化、重发或改写历史。

Lark草稿仍使用原共享邮箱 `collab@itea.sg` 与同一发送接口。图文邮件为 `multipart/related`，内含 `multipart/alternative` 的UTF-8纯文字和HTML两种正文，以及带固定Content-ID的内嵌PNG Logo；HTML使用CID引用，不依赖外部图片网址或浏览器专用data URI。网页预览用相同PNG的data URI。不能显示HTML的邮箱仍可读取完整纯文字正文。

## 网页与权限

通知设置的四类示例、待发邀约核对、通知查看和催促核对均可查看图文版，并展开纯文字版本。示例预览使用当前未保存输入，不发送邮件。预览iframe使用空sandbox和no-referrer。现有发信前确认、摘要核对、发送未知状态阻止重试、提醒冷却与待审核暂停提醒均保留；不打开自动催促开关。

只读工作流与通知接口采用已有字段白名单，不暴露 `mailDesign` 里的专属链接。没有新增收件人、发信入口、邮箱授权范围、线上迁移或依赖。应用后仍需正常审核和确认，更新本身不会发送任何邮件。

## 验证

`npm run test:mail-design` 使用合成数据验证四种HTML、双语逐项排列、字段配对／不等长完整保留、旧标准升级／自定义保留、单个居中原版Logo、无Slogan与页脚Logo、输入转义和链接限制、沙盒预览、版本化快照；模拟Lark草稿请求，使用Python标准库解析MIME并逐字节核对纯文字、HTML、CID图片。历史纯文字发送路径保持原样。

另检查真实本地HTTP／Chromium的四类设置预览、320／390px及桌面排版、品牌图片、已保存与未保存预览、纯文字回退，以及现有邀约、合作确认、发券、催促、权限、部署子路径和邮箱错误处理。全部使用隔离SQLite与模拟邮箱请求，不发送实际邮件或修改生产资料。浏览器排版和标准MIME解析不等于已在所有实际邮件客户端完成投递验证。
