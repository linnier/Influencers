# 2.7.1 项目共同负责人

管理员进入「系统管理 → 分配项目负责人」，选择项目，勾选两位或更多已启用且绑定名称的负责人账号，再确认分配。原有单负责人项目继续使用，无需迁移；新增项目先沿用原创建流程，再在此处添加共同负责人。

每位项目负责人都能操作该项目的邀约、报名审核、预选方案、合作及 Post。项目名称仍仅管理员可改；达人基础资料和平台账号仍由达人原负责人或管理员修改；查阅权限保持。项目负责人名称及负责人筛选展示全部成员。

项目表原 `owner` 保留一位原负责人供旧功能和 Lark 表兼容。共同负责人保存在现有「协作工作流」表的 `project-team` 行，不新增 Lark 表或字段，也不把两个人名拼进原负责人字段。读取时生成只读 `coOwners`，普通资料保存不写回此字段，服务端根据最新可信工作流记录校验权限。记录绑定当前主负责人，Lark 手动更改主负责人后旧共同负责人不再有效；需在系统管理重新分配。

分配操作在写锁中核对原成员，避免覆盖其他管理员刚保存的分配。停用或批量交接负责人时同步替换其共同负责人关系。业务记录和工作流属于不同写入：若保存中断，页面会提示失败，重新读取实际成员后再分配；不会自动重试授予权限。

备份中的工作流已包含此记录。验证涵盖两位负责人实际 HTTP 写入与邀约、跨项目拒绝、达人资料隔离、防伪造成员、移除后撤权、重启、交接/停用、系统管理勾选保存和筛选，以及 Lark 选择性读取。
