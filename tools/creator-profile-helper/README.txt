itea 自动发现达人 / 资料卡邮箱采集助手 1.5.1（试用版）

升级：完整解压覆盖原扩展目录，在 edge://extensions 或 chrome://extensions 点击“重新加载”，确认版本 1.5.1；关闭旧任务页重新打开。
首次安装：解压 ZIP，在扩展管理页开启开发者模式，点击“加载解压缩的扩展”，选含 manifest.json 的文件夹。

自动保存：
1. 保持 https://47.86.198.65/creators/ 的系统标签页已登录。
2. 在助手点击“连接系统并自动保存”，授权这个系统网址一次。
3. 之后单页“读取当前主页资料卡”和批量任务都会先自动保存到本机，再同步到系统“达人发现”。无需复制粘贴。
4. 登录过期、系统页面关闭或网络故障时，结果留在本机待同步，不显示为已存系统。恢复后点击“重试待保存线索”。
5. 连接绑定当时的系统账号；若登录账号发生变化，需要重新连接。其他账号的待保存记录不会自动转移。
6. 正式导入达人库仍在系统中确认，不自动发邮件、不修改其他业务。
7. 本机最多保留300条；仅自动淘汰已经同步的旧记录。待保存达到上限时暂停，先同步或导出备份。

粉丝数：
- 优先读取公开粉丝字段和完整数字提示，支持按“Followers / 粉丝”标签定位数值。
- 4.1万 / 41K 直接换算为41000显示、筛选和保存；后台保留原展示值以便核对。
- 粉丝筛选会标记“符合 / 范围外 / 待核实”。所有含邮箱线索仍自动保存，避免丢失；系统中可再次筛选。
- 换算数字可直接导入达人库；备注保留原始展示值和换算说明。

自动发现：
1. 打开扩展 →“关键词自动发现 / 批量任务”。填写关键词、平台、100、200或300位（也可小批量10–30位）和可选粉丝范围。
2. 点击开始并授权所选平台。助手按目标数量滚动搜索，最多120轮；Instagram找到新作者就立即读取主页并保存，不再等全部帖子解析完。目标最多300个去重主页；分批读取后继续发现。每次继续最多新增解析目标数20倍的帖子（上限6000篇）；来源不足显示缺口，可继续或更换关键词。
3. 有公开邮箱保留、无邮箱跳过；验证、登录、限制或无法可靠读取时暂停。可查看工作标签页后继续或跳过。
4. 保留任务页；关闭或刷新后会暂停，可继续原进度。不要手动切换工作标签页到其他账号。
5. 如帖子布局识别失败，可点击“复制页面诊断”反馈。诊断不含页面HTML或登录凭据。

边界：
平台真实页面结构、地区跳转和登录要求仍可能导致失败；模拟测试不代表所有真实账号都可读取。
地区关键词不代表已核实常驻地区，公开邮箱不保证可投递。
只读搜索结果与公开资料卡，不读取Cookie、密码、私信，不调用隐藏接口，不追查关联网站。
自动任务逐个执行，不通过并行大量开页提速。数据服务通常更快但可能收费，当前版本未接入新服务。

权限：activeTab、scripting、clipboardWrite、storage；按点击请求Instagram/TikTok和固定系统网址的可选网页权限，无所有网站权限、无常驻后台服务。
系统保存使用你已登录的系统标签页发起同源请求，服务器继续执行账号、权限和来源校验；不保存登录密码或令牌。

1.2.1：Instagram 粉丝链接可在简介之外，支持完整数字提示、拆分计数及“位粉丝/追蹤者”等本地化标签。读到邮箱后会短暂等待延迟出现的粉丝字段。已有结果可点“补全当前结果粉丝数”，不会重新搜索，按同一主页更新原结果和自动同步。无法读取时可复制页面诊断。纯标点加@账号不再当成邮箱；旧的疑似邮箱由你核对，不会自动删除。

1.2.2：帖子媒体按位置而不是DOM顺序核对，多个媒体会与作者栏逐一匹配。对只有下方推荐图暴露为img的播放器，结合顶部首个账号、头像、菜单和评论滚动区排除确认作者。诊断会包含全部候选媒体矩形，避免把推荐图片作为唯一参照。

1.3.0 批量与效率：
- 默认100位，可选200/300位，链接批量和粉丝补全也支持300位；300是扫描目标，不保证300个邮箱。
- 读取页面在后台打开，避免反复切走任务页；建议保持浏览器及任务页打开，验证时点“查看工作标签页”。
- 页面正文可读取即开始解析，不再等待视频图片全部加载。快速模式额外间隔0.8秒，平稳模式2秒；真正遇到平台限制仍暂停，不绕过验证。
- 默认跳过当前系统账号最近7天已读过的主页，包括无邮箱结果。失败/验证码不写入已读缓存。取消勾选可重新读取；补全粉丝数自动忽略缓存。最多保留3000条无联系方式的已读网址记录。
- 本机结果仍逐条持久保存，系统约每10秒或满10条自动分批同步；任务结束或暂停会继续提交待保存结果。每个请求最多30条，不受大任务数量影响。
- 系统网络同步不再占用本机记录写入锁；旧请求返回时不会覆盖后来更新的资料。
- 系统正式入库预览及确认支持一次最多300位，仍核对负责人、重复账号和邮箱，不自动合并或发邮件。
- 任务只显示最近80条日志；完整结果和已读数量保留，降低大批量页面重绘开销。

1.3.1：TikTok 默认按视频/图文内容关键词搜索（/search?q=），不再默认用用户搜索。视频结果链接含作者账号，直接去重读取作者主页，不逐篇打开TikTok视频；“账号名称/昵称”保留为可选搜索方式（/search/user?q=）。更换搜索方式应开始新任务，旧队列保留原进度。平台排序决定内容相关性，仍需核对实际地区和合作适配性。

1.4.0：目标按去重主页计数，分批识别作者后继续加载搜索结果补足目标。无邮箱主页仍在主页清单，可下载全部链接。暂时没有更多来源会显示缺口，支持继续加载及修改关键词续采；多个关键词用分号分隔。300 指300个不同的新主页，不保证当前来源能提供足够结果，也不表示300个邮箱。

1.4.1：无邮箱主页直接跳过，只保留及导出有公开邮箱的达人。300仍是扫描不同主页的目标，不表示保留300条邮箱线索。任务队列及已读去重记录仅用于断点续采和避免重复访问。

1.5.0：扫描结果支持每页10/20/50位、搜索/平台/粉丝筛选、跨页勾选和详情侧栏。连接同一系统账号后显示未入库/已入库；未连接、断线或无法核对时单列状态待核对。状态只读取系统现有资料，不自动入库。无邮箱仍不保留。

1.5.1：搜索页按实际结果容器滚动，空结果会等待延迟加载。滚动仍在推进或页面仍加载时不计为空轮；重试会先触发滚动。停滞时说明后台、加载或滚动状态，可直接查看搜索页及复制公开布局诊断。主页目标、邮箱保留和入库流程不变。
可选“搜索页保持前台”：由用户启用，适用于平台在后台暂停加载；只激活搜索页，资料卡工作页仍在后台，不读取账号登录凭据。
