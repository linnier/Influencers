# 自建公开资料采集小测

独立 Python 3 标准库脚本，与网站进程及数据库无连接。用于在实际服务器上验证免费公开读取的可行性和进程资源，不是已经接入网站的完整关键词搜索器。

## 执行

在服务器 SSH 中，把本提交的 `tools/creator-crawler-pilot.py` 导出到 `/tmp/itea-crawler-pilot.py`，运行：

```sh
python3 /tmp/itea-crawler-pilot.py
```

可选 `--keyword food --region Singapore`；默认即为这两个公开条件。无需 API Key、pip 安装、浏览器或 Docker 操作。无需切换网站提交、重启容器或读取应用环境变量。

脚本会串行检查 robots.txt，再读取三个公开合作/个人网站和两个平台主页样本；关键词阶段只试读 Bing 的公开 RSS，如 robots.txt 不允许、来源不可读或格式异常，会报告原因，不把它当成“0个达人”。若得到完整平台主页候选，最多再检查两个。该公开 RSS 不是保证可用的正式 API，也不替代稳定的达人搜索服务。

固定样本只为测读取能力：DanielFoodDiary 官网广告合作页、Sophie Ong 官网、Nicole Low 的公开合作资料页、DanielFoodDiary 的 Instagram 和 TikTok 主页。不表示这些达人适合某项合作，也不发送邀约。

## 边界

- 单任务，最多14次HTTP尝试、90秒墙钟时间、约8MiB响应正文、每页2MiB；每次请求最多8秒，两次请求间隔至少0.8秒。
- 在 Linux 主程序中尝试设置256MiB进程地址空间和10秒CPU软上限，达到CPU或墙钟上限停止并保存当前报告。不是占用或预留256MiB内存；实际峰值另行测量。
- 只读取固定允许域名的 HTTPS 页面；无 Cookie、登录或付费 API；拒绝超出允许域的重定向，拒绝登录/验证页，不重试403/429，不绕过站点限制。
- robots.txt 不允许或无法确认时跳过；404/410视为未设置规则。不会以读取失败推断“没有邮箱”。
- 平台粉丝数只接受与目标账号匹配的结构化整数。未知保留为空，实际0保留0；不把12.3K换算成已核实数字。
- 公开网站只从可见正文和 mailto 链接提取邮箱；不从隐藏脚本提取网站邮箱。保留来源与少量摘录，邮箱可投递性未验证。
- 仅在新建的 `/tmp/itea-crawler-pilot-*` 目录保存 JSON 和 CSV，CSV防公式注入。未抓取应用数据或环境配置，未导入达人库，未改网站源文件。

## 报告解读

报告包含每个目标的HTTP结果、跳过/失败原因、耗时、公开邮箱、明确粉丝数和来源，以及本进程的峰值RSS、CPU时间、响应正文下载量、请求尝试数与前后系统快照。

网络出口拦截与网站返回403应区别解读；不能用开发环境的网络拦截推断生产服务器的采集结果。进程峰值内存不是整台服务器或浏览器采集的内存成本；正文下载量也不含TLS和网络头部开销。前后系统快照不是对网站影响的严格压测。

## TikTok 单项复测

第一轮用户服务器试采耗时9.63秒、峰值RSS 25.96MiB、CPU时间0.118秒，5个目标中两个公开网站可读并发现2个去重后的公开邮箱。TikTok在读取 robots.txt 时超过旧的64KiB限制，因此尚未访问该主页；不能从这条结果推断TikTok禁止采集。

现将 robots.txt 上限提高到512KiB，保留每页2MiB和总正文约8MiB的边界。增加规则内容类型、正文大小、HTTP结果和最终路径判断的诊断记录。规则支持通配符、结束锚点、最长路径优先、相同长度允许优先及重复匹配分组；要求的Crawl-delay在后续请求中生效，超过剩余测试时间则跳过。

```sh
python3 /tmp/itea-crawler-pilot.py --only-tiktok
```

该模式只检查一个固定 TikTok 主页及其 robots.txt，不再请求搜索源或重复其他四个样本。正常无重定向时仅需2次HTTP请求；如果规则明确禁止，则只检查 robots.txt 并记录匹配规则。正文或规则仍超过读取上限、需要登录或验证、或返回403/429时停止该项。没有使用浏览器、Cookie、代理池或账号，也没有修改应用代码或数据。

新增大于64KiB规则文件、超过512KiB仍停止、通配符/分组/规则优先级、单项模式不访问其他站点的离线回归测试。该轮真实结果仍需在用户服务器执行后确认。
